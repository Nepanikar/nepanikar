# Architecture

## Startup — `lib/main.dart` → `setup()` in `lib/utils/app_setup.dart`

`setup()` runs before `runApp`, in order:
1. Firebase (Crashlytics catches `FlutterError.onError` + async errors; Analytics).
2. Registers `GoRouter`, navigator key.
3. `SaveDirectories` → `DatabaseService.init()` (opens sembast, inits all module DAOs).
4. `NotificationsService` (AwesomeNotifications, wired to the router for deep links).
5. `ExportService`, `AppConfig` (store/play ids, package info).
6. Precaches SVGs, inits `LottieCacheManager`, `ContactsDataManager`, `BpdWeeksDataManager`.

## Dependency injection — GetIt via `registry`

`lib/utils/registry.dart` exposes one global:
```dart
final registry = GetIt.instance;
```
- Register in `setup()` (services) or in each DAO's `init()` (DAOs self-register).
- Access anywhere: `registry.get<UserSettingsDao>()`. Screens commonly expose a getter:
  ```dart
  UserSettingsDao get _userSettingsDao => registry.get<UserSettingsDao>();
  ```
- Don't pass services through constructors when they're in the registry — just `get` them.

## Routing — GoRouter typed routes (codegen)

- All routes declared in `lib/app/router/routes.dart`, grouped into `const` lists
  (`_settingsRoutes`, `_gameRoutes`, `_contactRoutes`, `_homeRoutes`, `_myRecordsTestRoutes`,
  `_bpdProgrammeRoutes`) all nested under the root `MainRoute` (`path: '/'`).
- `part 'routes.g.dart';` is generated by `go_router_builder`. **Run build_runner after editing.**
- Config + analytics in `lib/app/router/go_router_config.dart`: `GoRouterObserver` logs every
  screen view to Firebase Analytics automatically — no manual screen tracking needed.

### Defining a route (pattern used across the app)
A screen file declares its own typed route next to the widget:
```dart
@TypedGoRoute<AnxietyAppRoute>(path: '/home/anxiety')
class AnxietyAppRoute extends GoRouteData with $AnxietyAppRoute {
  const AnxietyAppRoute();
  @override
  Widget build(BuildContext context, _) => const AnxietyAppScreen();
}
```
Then add the `TypedGoRoute<AnxietyAppRoute>(path: 'home/anxiety')` entry to the relevant list
in `routes.dart` so it nests under `MainRoute`.

### Navigating
```dart
context.push(const BreathingExercisesRoute().location);   // push
context.go(const MainRoute().location);                   // replace stack
context.push(SomeRoute(id).location, extra: payload);     // with params/extra
```
Path params (e.g. `:testId`, `:weekNumber`) become constructor args on the generated route class.

## Database — sembast (NoSQL) + per-module DAOs

`lib/services/db/database_service.dart` is the coordinator:
- Opens `app.db` (version 1) in the app documents dir.
- `_initModuleDaos()` builds `UserSettingsDao` + one `*ModuleDb` per feature:
  depression, self_harm, suicidal_thoughts, eating_disorder, my_records, my_contacts, bpd,
  plus `EmotionsDao`.
- First launch: if old-app data exists (Android config file / iOS SharedPreferences) it migrates
  via `nepanikar_data_migration`; otherwise `preloadDefaultData(l10n)` seeds defaults.
- `clearAll()` wipes every module (used by export/reset).

### Module + DAO pattern
- `XModuleDb` (e.g. `SelfHarmModuleDb`) has `initModuleDaos()`, `preloadDefaultModuleData(l10n)`,
  `clearModule()`, `doModuleOldVersionMigration(config)`.
- Each DAO owns a sembast store keyed by a `_storeKeyName`, and self-registers in `registry`:
  ```dart
  class SelfHarmPlanDao extends NepanikarPlanFormDao {
    SelfHarmPlanDao({required super.dbService}) : super(storeKeyName: _storeKeyName);
    @override
    Future<SelfHarmPlanDao> init() async {
      registry.registerSingleton<SelfHarmPlanDao>(this);
      return this;
    }
    static const _storeKeyName = 'self_harm_plan';
  }
  ```
- Common reusable DAO bases in `lib/services/db/common/`:
  `NepanikarPlanFormDao`, `NepanikarListFormDao`, `NepanikarChecklistFormDao` — extend these for
  the standard plan/list/checklist features instead of writing store logic by hand.
- DAOs expose **streams** for reactive UI. UI reads them with `StreamBuilder`. Example:
  `UserSettingsDao.localeStream`, `themeModeStream`, mainColor stream drive the whole app theme.

### Models
- `@freezed` + `@JsonSerializable` → generated `*.freezed.dart` and `*.g.dart`.
- After editing a model, run build_runner. Generated files are git-tracked and checked by
  `test/ensure_build_runner_test.dart`.

## State management — Provider

- App-level `ChangeNotifier`s registered in `lib/main.dart`: `MoodChartFilterProvider`,
  `MoodHeatmapFilterProvider`, `MoodState` (see `lib/providers/`).
- For service/db reactive data, prefer DAO streams + `StreamBuilder` over Provider.

## Services worth knowing — `lib/services/`

- `DatabaseService` — DB coordinator (above).
- `NotificationsService` — AwesomeNotifications, schedules + routes notification taps.
- `ExportService` — exports user data from the DB.
- `SaveDirectories` — resolves app file paths (db dir, old-app config/backup paths).
- `ContactsDataManager` / `BpdWeeksDataManager` — load JSON-driven content from `assets/`.
